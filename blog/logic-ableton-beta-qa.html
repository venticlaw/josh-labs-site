Product QA

The first product test is boring on purpose.

Before a plugin gets interesting, it has to open. If a producer installs a plugin and it does not show up in the DAW, the product promise is already broken.

The first Fix Your Sound beta test is basic: install, scan, open, play audio, save the session, reopen the session, and report what broke.

Logic has its own path

On Mac, Apple documents Audio Units plug-ins as `.component` files in Audio plug-in locations, including system and user Library paths. Logic Pro uses Audio Units, and Apple points users to Plug-in Manager if an Audio Unit does not appear or needs to be activated.

That means a real beta cannot just say it works on Mac. It has to prove it appears in Logic, opens, processes audio, and survives normal session behavior.

Ableton has its own path too

Ableton documents plug-in setup through Live's Plug-Ins browser and preferences. Its help docs also explain common cases where VST or AU plug-ins do not appear, including rescanning plug-ins and checking system folders.

That means Ableton QA has to be its own checklist. Not assumed. Tested.

Why this matters

Investors like AI. Producers like tools that do not waste their night. Both are true, but the beta has to earn trust at the bottom layer first.

If it does not scan, the AI does not matter.

That is why the campaign should show install quality as proof, not just feature hype.
